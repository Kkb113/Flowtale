# Publication deletion deployment

Before deploying publication cleanup to existing storage, stop application writers and back up the database and object storage. Run `node jobs/scripts/index-publication-aliases.js` with `ASSET_BUCKET_NAME`, `PVT_ASSET_BUCKET_NAME`, `AWS_S3_REGION`, `FABLE_ASSET_ROOT` and `FABLE_PROFILE` set to the deployment values. Local storage also needs `AWS_S3_ENDPOINT=http://localhost:14566` and the local fixture credentials. Dry run is the default. Resolve invalid records, then run with `--apply --maintenance-confirmed` and repeat the dry run to verify zero changes.

The script groups existing `ptour` and `pdh` metadata by immutable asset hash, including renamed aliases, and writes verified private alias registries. It preserves previously indexed aliases and does not delete publications. Deploy the API after the backfill. Existing published demos without a registry deliberately reject publication changes/deletion until migration is complete; guessing the historical aliases would leave content accessible.

For the AWS CDN deployment, set `FABLE_CLOUDFRONT_DISTRIBUTION_ID` to the distribution serving the configured asset hostname. Give the API role `cloudfront:CreateInvalidation` and `cloudfront:GetInvalidation` access on that distribution. Verify the hostname/distribution association during deployment. Direct storage deployments, including local fixtures, leave the CDN setting empty and need no CloudFront credentials. A configured CDN without an invalidation distribution rejects deletion before removing objects.

Deletion runs under the existing demo row lock. It removes every tracked alias's public prefix, all public tour/hub versions for the asset hash, and the tour-owned screen snapshot namespace. Private draft documents, source screens and shared media are retained. Object listing verifies removal. The API then waits for CDN invalidation to complete before committing the deleted state. Storage/provider failures or a pending invalidation return an error, retaining the dashboard item for retry. A partially removed publication can be unavailable during recovery; the error is never reported as completed deletion. Retrying safely repeats removal and invalidation. No aggregate SQL/object-store transaction is claimed.

An unusually long rename history invalidates its containing public cache namespaces to stay within CloudFront wildcard limits; this only evicts cache entries and does not remove other demos' storage. Cached browser copies and files previously downloaded by viewers cannot be recalled. Historical raw draft denial remains governed by `draft-storage-migration.md`; this cleanup does not implement secure redaction of published screen content.

Local verification on September 5: indexed 39 publications with read-back verification; real publication tests create five versions and two renames, verify the public JSON before deletion, and require HTTP 404 for all aliases, manifests and versioned tour files afterward.
